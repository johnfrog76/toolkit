# Known gaps

What the product does not do yet, and what you see if you try. If you hit one of these, this list is the
answer, not a bug report. Each row names the GitHub issue that carries it, and the row goes when that
issue closes. The root [README](../README.md) links here.

| Gap | What you see | Issue |
| --- | --- | --- |
| **Teams recipients live in two places** | The manager recipient is read from the top-level `managerWorkflow`, and every other recipient belongs to a Space. The Environment card says which block each recipient came from (`communication.recipients[].scope`), which is why switching Space changes one list and not the other. This is how it works today, not a defect | #46 |
| **Create PR from the browser reads the card, not your checkout** | The bridge runs verbs in the Toolkit's folder, so *Create PR* takes the project from the card's `ADO Link` and the source branch from its `## Branch` section, and refuses when either is missing. Running the verb in the card's own code checkout (`<wsRoot>/<repo>`) is not built, so the branch must already be pushed; `NewPR` checks that it is and, if not, says which `git push` to run | #311 |
| **A meeting row still draws three buttons** | Every other row has one exposed action and the rest in the `...` menu ([One grammar for dialogs and row actions](../web/README.md#one-grammar-for-dialogs-and-row-actions)), but a 1:1 row shows Close, Edit / send and View details side by side | #69 |
| **A repository's designs move from a terminal only, and searching inside one sees the default branch** | The Design tab and Hub Designs group the four folders by state, read the archive and search it; `MoveDesign` moves a design in the repository you stand in, or in the hub. A repository's rows carry no move in the browser, because a Space does not yet know where its checkout is. A repository's Search inside is GitHub's code search: the default branch only, minutes behind a push, and rate-limited. The note under the results says so, and a search that cannot run says why in its row. A product whose files carry no `id:` shows a count and names the stamp, not its designs ([Designs](hub/design.md)) | #312 |
| **`Config -Set` cannot declare a Teams recipient, and a person's recipient must be `"type": "channel"`** | The schema is built from the shipped keys, where `manager` is the only recipient, so `tkConfig -Set managerWorkflow.communication.recipients.mom.display=...` answers `Unknown setting`. A second recipient is hand-edited into `config.local.json`, and `"type"` must be `"channel"` even for a chat (`"chat"` is refused as `unsupported type`). [How to get a webhook URL](modules/communication.md#getting-a-webhook-url) | #144 |
| **There is no backlog of cards and no "plan it for later"** | A card is in play the moment it is made; this is deliberate for now. A GitHub Space's Issues tab lists the tracker's backlog, and a card is still made only when the work starts | #313 |
| **With Azure DevOps not in use, its verbs are hidden, not gone** | `Menu`, `Setup`, the New card dialog and Settings show a machine with no ADO only what it can use. The eleven ADO verbs are still registered, though: typed by name (`tkMyWork`) they answer with their tier sentence, the bridge still runs them, and the ADO routes still exist | #315 |
| **Daily shows this week and last week, and only in the browser** | A timesheet three weeks late has no page, and the CLI cannot read a week at all | #17 |
| **The Docs tab reads one repository's docs, and only reads them** | The filter drawer narrows the `docs/` tree by title and path; there is no search inside the documents' text, and none across other repositories' docs. A document is not edited in the room: a change is a commit in its repository. An image past the 10 MB the asset route serves is a broken image in the room (the agent answers 413 and says so); it opens on GitHub | to be filed |
| **Team Agile's standup fills only the walk queue, and plays in a first cut** | `Standup` and its tab print the standup as text. The tab's Play plays it on the Remote Standup's stage with the browser's voice: one tile a worker label, the week's seat always ghosted, no neural voice. A GitHub Space fills from its issues and a local Space from its cards. An Azure DevOps Space prints the ritual with "Azure DevOps is the human team's board ..." on its Tracker line, and the queue's `decide` and `look` are empty until their labels are named ([Team Agile](modules/solitaire-agile.md#known-gaps)) | #317 |
| **Team Agile's dressed standup is the played view's alone** | By design: the guard holds one worker sentence against its group's facts, so only those sentences are dressed and only the played view reads them. The page's Work grain, Copy and `Standup -Grain work` carry the derived prose, the same on every machine. With no model key, a model that fails, or a group the guard refuses (a persona's proper noun is read by its capital), the stage speaks the prose and says nothing about it: the reason is in the usage log (`spoken: null`) and `GET /api/env`'s `anthropicConfigured`. A visible marker on the stage would be a code change, not filed ([where the dressed text shows](modules/solitaire-agile.md#the-agentic-layer)) | #319 |
| **The Studio's foyer counts issues and deploys, not designs or specs; Promote files only into the Space you are in** | A GitHub row says how a product's ledger stands and its last deploy, with no count of designs in flight or specs. A hub note for another Space shows Promote disabled with "switch to it first". Promotion opens the thread; moving the note into its product's repository is a commit nothing offers, and a thread is read, not answered, in the room ([the Studio](modules/studio.md#known-gaps)) | #90 |
| **A retired Space is still on the avatar menu's Space list** | `RetireSpace` sets `status: archive`: the Spaces card files the Space under Archive and nothing asks its tracker, but the switcher still offers it. The rule for what the switcher offers (`Select-OfferedSpaces.ps1`, `offered_spaces`) hides only the dismissed demos. To take a Space off every list, `RemoveSpace` it: the folder and its cards stay | #166 |
| **Every Space is read by the one `gh` login** | New Space, the Spaces card and every GitHub read ask `gh` as whoever it is signed in as. A work account beside a personal one is not built: a repository only the other login can see reads `Visibility unknown` and `not visible to this login` in New Space's **Add owner/name** row, and can still be added; switching accounts is `gh auth switch`, in a terminal, for every Space at once ([the Studio](modules/studio.md#known-gaps)) | #320 |
| **The landing page is built and not deployed yet** | `npm run build:landing` builds the page ([`web/README.md`, "The landing page"](../web/README.md#the-landing-page)): the banner with the commercial playing, the three ways of working with the cast in their windows, quick start and the footer. Not yet: the deploy, which waits for the public repository (`pages.yml` runs on the button only); the links both ways between the README, the app's Home and the page, which wait for the page's address. | #29 |
| **The first run has no Welcome page and no tutorial cards** | `tkStart` lands you on a populated board. With the deck module on, Home's first-run banner offers the intro deck; nothing walks you through the board itself | #20 |
| **A Teams webhook exported in your shell is not seen** | `SendTeams` posts through the running agent, which reads the `TEAMS_WEBHOOK_*` variables from `.env` in the package root when it starts. A variable set in the terminal you type in does nothing, and a change to `.env` needs the agent restarted (`tkWeb -Stop`, then `tkWeb -Dev`); "Not sent -- no webhook configured" names the variable that is missing | #144 |
| **The web UI is on TypeScript 6.0, not 7** | TypeScript 6.0.3 is in, pinned exactly; `npm outdated` in `web/` still lists `typescript` against 7.0.2, the one major left. 7 waits on two peers: ts-jest (latest 29.4.14) peers `typescript >=4.3 <7`, and typescript-eslint (latest 8.71.1) peers `>=4.8.4 <6.1.0`; with 7 installed `npm ci` refuses with ERESOLVE. It moves when both widen, or when the suites leave ts-jest, which is a decision of its own | #268 |

Three more things are true by design rather than by omission, and are not on that list: the deck
narration route (`POST /narrate`) is not served by this agent ([the agent overview](ARCHITECTURE.md#the-agent)),
the `Sync` test suite skips rather than passes when the store has no pre-commit hook ([Testing](TESTING.md)), and
a growth or communication route returning 404 with its flag **off** is the design working, not a
missing route ([the modules guide](modules/README.md)).
